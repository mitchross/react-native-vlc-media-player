# Known Issues and Limitations

This document tracks known issues and limitations in the current implementation of the new architecture support.

## iOS Fabric Event Handling

**Status:** ✅ Resolved (as of 2024)  
**Previously Affected:** iOS with New Architecture Enabled in early versions

### Note

Earlier versions had partial iOS Fabric event handling implementation. This has been fully resolved in current versions. All events now work correctly on both iOS and Android with the new architecture enabled.

---

## Android ViewManagerDelegate Interface Compatibility

**Status:** Resolved (with CodeGen)  
**Affects:** Android with New Architecture Enabled  
**Severity:** Low

### Description

The Android implementation references `RCTVLCPlayerManagerDelegate` and `RCTVLCPlayerManagerInterface` which are generated by CodeGen. These files won't exist until CodeGen runs during the first build in a project with new architecture enabled.

### Impact

- First build may show warnings about missing generated files
- CodeGen will generate these files automatically
- Subsequent builds will work normally

### Solution

No action needed. This is expected behavior and will resolve automatically after the first build.

---

## Volume Property Type

**Status:** Not an Issue (By Design)  
**Affects:** All platforms  
**Severity:** None

### Description

The volume property is defined as `Int32` in the TypeScript spec but the Android ReactProp annotation shows `defaultFloat = 1.0f`.

### Explanation

This is intentional and correct:
- VLC expects integer volume values (0-100)
- The `defaultFloat` annotation is for React Native prop conversion
- The actual parameter is `int volume` and is cast to integer
- No breaking change - this matches the legacy implementation

---

## React Native Version Compatibility

**Status:** By Design  
**Affects:** React Native < 0.68  

### Description

New architecture support requires React Native 0.68 or higher.

### Workaround

- For RN < 0.68: Library continues to work with legacy architecture
- For RN 0.68+: Can optionally enable new architecture
- No breaking changes - backward compatibility maintained

---

## TypeScript Import Path

**Status:** Documentation  
**Affects:** TypeScript users  

### Description

For best TypeScript support with the new architecture, import from the specific path:

```typescript
// Recommended for TypeScript with new architecture
import { VLCPlayer } from 'react-native-vlc-media-player/src';

// Also works (uses automatic fallback)
import { VLCPlayer } from 'react-native-vlc-media-player';
```

Both work correctly, but the `/src` path provides better type inference.

## Reporting Issues

If you encounter issues not listed here:

1. Check if you're using React Native 0.68+
2. Verify new architecture is properly enabled (if applicable)
3. Test with legacy architecture to isolate the issue
4. Search existing issues: https://github.com/mitchross/react-native-vlc-media-player/issues
5. Create a new issue with:
   - React Native version
   - Platform (iOS/Android)
   - Architecture mode (legacy/new)
   - Minimal reproduction code
   - Full error message/logs
